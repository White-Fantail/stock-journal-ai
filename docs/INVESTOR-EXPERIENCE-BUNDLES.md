## 사용자 역할과 핵심 여정

### 대상 사용자
- A. 증권사 연결 없는 신규 사용자: 즉시 계획·관심종목·일지·위험 계산·점검 가능. 연결을 가입 선행조건으로 두지 않음.
- B. 소유자 개인 Tiger 접근 사용자: 원본 계좌/관측치와 직접 작성 기록을 분리. 임시 관측 수량/평가액을 검증 원장으로 격상하지 않음.
- C. 공식 Tiger OAuth 승인 대기 사용자: 승인을 기다리는 메시지와 무관하게 A의 독립 기능을 완전히 사용.
- D. 장기 이용자: 종목별 현재 계획→정기 자기평가→지난번 다음 행동 확인→필요하면 본인 승인 후 개정.

### 1차 내비게이션 구조
- `홈` / `포트폴리오` / `투자일지` / `점검` / `더보기`(모바일).
- 점검 하위: 점검할 일 / 주간 점검 / 월간 복기 / AI 코칭.
- 더보기 하위: 거래 기록(원본/직접 입력 분리), 위험 계산기, 장기 성과(검증 조건을 갖췄을 때), 증권사 연결, 설정, 필요 시 AI 종목 분석.
- 기존 URL은 삭제/단절하지 않고 유지한다. 신규 집계 페이지는 명시적으로 라우팅하고 이전 경로에는 링크 혹은 호환 리다이렉트.
- 사용자가 가진 **종목**을 기준으로 포트폴리오→계획→해당 종목 복기→보고서까지 문맥(종목)을 이어간다. 테넌트 ID와 브로커 계좌 ID를 URL에 보내지 않는다.

### 보유/출처 표현 불변식
- 현재 계좌 스냅샷: `관측` + 기준 시각 + 통화 + 계좌 범위, 확정 실현/미실현손익 아님.
- 독립 검증 거래 원장: `검증` + 버전 + 완전성 범위, 현재 시세가 아님.
- 사용자 작성 내용: `내가 작성` + 계획 수정 이력, 실제 주문·자동 위험 조치 아님.
- 자료 없음: `확인되지 않음`; 절대 임의 0/가상 총수익률/가짜 건강점수 표시 금지.
- 여러 통화, 다른 관측 시점, 일부 누락, 계좌 밖 자산에는 전역 합계/위험 준수 판단 금지.

### B1 — 3단계 첫 시작 / 나의 투자 원칙 (선택형 초기 설정)
**목표**: 브로커 없이도 사용자 최초 가치를 제공.
**변경 후보**: 신규 `/private/getting-started`, `/private/principles`; 홈의 최초 진입; 사용자 작성 설정 API. 저장이 필요하면 **새로운 add-only migration 026 이상**을 검토하고 버전 중복 여부 확인.
**3단계**: (1) 투자 목적·예상 시점·기준 통화, (2) 본인이 감수 가능한 한계/단일종목 비중/점검 리듬(선택), (3) 첫 종목 계획/관심 기록 또는 건너뛰기. 언제든 수정, 미입력 가능. 원칙은 질문/설명으로 유도하며 적합성 평가나 투자자문처럼 자동 판정하지 않음.
**완료 기준**: 승인 대기 일반 유저도 3분 이내 첫 계획 생성 가능(사용성 목표, 실제 측정 필요); 건너뛰기/재방문 가능; 기존 종목별 `maxAllocationPct`와 '개인 전체 포트폴리오 정책' 기준이 섞이지 않음; 금전/건강/민감한 프로파일을 분석 공급자로 자동 전송하지 않음.
**테스트**: 신규/기존/비연동/권한대기, 모든 값 미입력, 수정 이력, 서버 소유권, A/B 차단, export/delete 대응.

### B2 — 대시보드 '오늘 확인할 일' (투자 판단 큐)
**목표**: 숫자·메뉴 대신 사용자가 취할 수 있는 1~3개 조치를 보여줌.
**변경 후보**: `app/private/page.tsx`; 새 pure `lib/next-review-actions.ts`; 증거 데이터 기존 `review-schedule.ts`, `notification-signals.ts`, 집중도/계획 조회.
**우선순위**: 읽을 수 있는 기록에 중대한 결함(재연결/검증 불가) → 기한 지난 사용자 주기 점검 → 계획 없는 보유 종목 → 검증 가능한 범위에서 사용자가 정한 비중 기준 검토 → 지난 자기평가의 미확인 다음 행동. 한 번에 최대 3개; 이유/기준 시점/실행 링크/표시 불가능한 이유를 명확히. 브로커와 무관한 원칙 설정은 비연결 신규 사용자에게 우선.
**완료 기준**: 중복 미표시, 읽기 오류가 '할 일 없음'으로 바뀌지 않음, 클릭 시 해당 종목/점검 흐름으로 이동, 절대 매수·매도 권고·시세알림 생성하지 않음.
**테스트**: 전체 실패/부분 실패/타임존/빈 계정/연결 대기/관측치 낡음/복수 계좌/200건 상한.

**목표**: 데이터 상태가 아니라 집중·분산 리스크를 이해하고 자기 원칙을 검토.

**작업**: 최상단 출처·시각·계좌 범위 한 줄, 표시 가능한 보유 요약, 단일 종목/상위 종목 집중도와 위험 요인(사용자 직접 분류) 우선. 계획 부재·위험군 미분류의 종목별 CTA. 진단 상세는 접어두기. 완전성 불충족 시 비교를 하지 않고 대신 기록/계획 작성 유도.

**목표**: 투자자가 폼보다 '생각을 정리'하는 데 집중.
**변경 후보**: `app/private/journal/{page.tsx,journal-workspace.tsx,new/page.tsx,review/new/page.tsx}`, symbol-picker.
**작업**: 종목 상세 첫 영역에 현재 투자 논리·다음 검토 조건·점검 예정일·마지막 자기평가 표시. 작성은 별도 페이지 유지, 모드별 단계적 공개: 기본(왜/어떤 조건에서 다시 볼까/언제 점검)과 선택(목표·손절·투자 기간·비중) 구분. 거래가 존재하면 '이 기록에 판단 붙이기'를 뚜렷이 하되 관측 주문과 독립 검증 체결을 혼동시키지 않음. 수정은 새로운 append-only revision.
**완료 기준**: 목록에 인라인 편집폼 없음; 보유 종목 일지 2탭 내 도달; 선택 종목 보존; 다시 저장해도 이전 판단/출처 링크 손실 없음; 작성 필드 건너뛰기를 선택한 경우 미설정 그대로 유지.
**테스트**: 신규/기존 계획, 동일 티커 다른 계좌, 관측/검증/수기 정보, 검색·접근성, 이력 재현, 오래된 계획에 대한 자기평가 차단.

### B5 — 점검 센터 통합 및 '다음 행동' 폐쇄 루프
**목표**: 복기가 정기적으로 실제 행동 습관 개선으로 연결.
**변경 후보**: `app/private/alerts/page.tsx`, `reports/weekly/page.tsx`, `reports/monthly/page.tsx`, `journal/review/new/page.tsx`; 새로운 `/private/review` 허브.
**작업**: 주간 할 일/기한 도래/지난 자기평가의 본인이 적은 다음 행동을 먼저 표시. 월간 보고서 집계는 유지하며 다음 점검에 보여줄 행동 상태를 사용자 '했다/아직/해당 없음/판단 유보'로 직접 기록하도록 지원. 독립된 변경 기록으로 저장(필요하면 add-only 027+), 자동 실행 완료 판정 금지. AI 코칭은 보조 카드로 연결. 날짜 없는 EVENT_DRIVEN은 임의 마감일 부여 금지.
**완료 기준**: 점검 작성 후 같은 '기한 지남' 항목 중복/오표시 없음; 다음 행동은 사용자가 직접 완료 표시; 오래된 월간 기록/다른 종목 맥락 보존.
**테스트**: 경계 주간/월말 NZ timezone, 여러 복기, 이전 행동 링크, 과거 기록 불변성, count 정확성, 200건 상한 fail closed.

**변경 후보**: `app/private/analysis/{page.tsx,analysis-panel.tsx,actions.ts}`, `lib/ai-analysis.ts`, `lib/coach-evidence.ts`.
**작업**: '이 종목 판단 돌아보기' 또는 '이번 달 투자 습관 돌아보기'의 상황별 시작. 코칭 답변은 구체적인 사용자 기록/날짜/불확실성 출처 인용, 강점/불확실성/다음 질문 중심. AI 제안을 실제 투자 원칙으로 자동 저장 금지; 사용자가 별도 작성 화면에서 직접 검토 후 저장. 매 호출 동의·전송 범위 공개/최소화, ZDR 검증 및 예산 유지.
**완료 기준**: 브로커 ID/수량/가격/금액 무승인 유출 없음; 근거가 없으면 AI가 아는 척하지 않음; 일일/월간 사용 한도 유지; 매수·매도·목표가 가격 제시 권고 금지.
**테스트**: 악성/위조 일지 텍스트, 데이터 누락, 모델 오류, 동의 해제, 인용 무결성, 외부 제공자 실패.

### B7 — 실제 사용자 검증·최종 개선/릴리스 게이트
**목표**: 소스 테스트에 그치지 않고 사용자가 기기에서 목표 행동을 완료하는지 검증.
**변경 후보**: E2E, 접근성, QA 가이드, 에러/빈 상태, 관측성(민감 정보 없는 이벤트만).
**작업**: 익명/첫 로그인/유저 A,B 격리/비연동/소유자 개인 Tiger/공식 OAuth 대기별 여정 실행. 실제 320·375·430px 스마트폰, 768·1024px 태블릿, 데스크톱 검증. 터치 영역·동적 오버플로·키보드·aria·스크린리더·리다이렉트·폼 오류/복귀/빈 상태 검증. 성공률/실패 화면/기능별 도달 단계 측정(금액·티커·메모는 telemetry 금지).
**완료 기준**: 주요 여정 ①첫 계획 작성 ②관측 보유→해당 종목 일지 ③계획 수정 ④자기평가 작성 ⑤다음 행동 확인 ⑥JSON 내보내기 성공; 프로덕션 적용 전에 보안/백업/실제 Google A/B·Tiger 권한 명세 확인.
**테스트**: 기존 CI+타입·빌드+브라우저 E2E+보안 A/B+실기기+계정 삭제 재검증.

## 종합 수용 기준(모든 번들 공통)

- 소스 구현은 `dev`에서만. 각 번들 독립 커밋/테스트; 메인 반영은 별도 명시 요청을 받고 **fast-forward만**, `main`만 운영 빌드.
- GitHub 공개 저장소에 고객 재무정보, 증권사 식별자, 스크린샷, API secrets, 실제 거래 텍스트, AI 원문 저장 금지.
- 모든 새 DB 테이블에 테넌트 경계/FORCE RLS, 적절한 제한 역할, export/delete, synthetic A/B, 마이그레이션 승인 매니페스트. 기존 SQL 체크섬 불변.
- 원본·추정·사용자 작성 구분, 누락/부분 데이터 fail closed, 통화·시각·출처 표시 필수.
- 퍼포먼스/비용: 기존 스냅샷 재사용; quote polling/시세 샘플 DB 저장 금지; 대시보드에서 불필요한 broker/AI read 무제한 반복 금지.
- 모바일은 CSS 문자열 존재 테스트만으로 완료 판정 금지. 실제 로그인 브라우저 터치/키보드/반응형 검증.
- 실현손익·정확한 포트폴리오 총수익률은 독립 원장 검증 게이트 그대로 유지. 현금흐름, FX, 기업행동의 근거가 없으면 미검증 유지.
- 이전 릴리스 문서의 시점 의존 상태(예: 'main 뒤처짐')는 현재 GitHub 분기 상태를 다시 확인하고 해석.

## 개발 순서·릴리스 스코프

1. **가장 먼저 B0+B1+B2**: 1차 일상 사용성과 신규 사용자 가치를 만드는 1차 릴리스 후보. B1이 저장 스키마를 추가한다면 DB gate 포함.
2. **이후 B3+B4**: 종목별 보유 위험과 계획-일지 간 작업 연결.
3. **이후 B5+B6**: 반복 점검과 AI의 현실적 효용.
4. **각 번들 테스트 + B7 전체 검증**: 소규모 배포 전후 연속 실행.

권장 출시 방식은 번들마다 dev 구현→독립 CI/PG/브라우저 검증→사용자 승인 시 FF main→기존 데이터 무중단 확인. 여러 번들을 한꺼번에 개발할 수 있어도 증거/QA는 번들 단위로 분리한다.

## 정량적인 제품 가설(출시 후 실제 검증 대상)

- 비연결 신규 사용자가 3분 내 첫 계획/기록 생성 (목표이며 측정 전 '달성' 주장 금지).
- 최상위 점검/계획 작업은 홈에서 2회 이하의 화면 전환으로 도달.
- 주간 점검 화면에서 사용자 작성 '다음 행동' 완료 상태까지 자연스럽게 도달.
- 잘못된 확정 수익률/전역 위험수치/출처 혼용 건수 0.
- 보안 A/B 누출, 불완전 데이터의 0으로 오표시, 동의 없는 AI 전송 0.
- 제품 지표는 개인 금액·티커·내용을 이벤트 로그에 넣지 않고 유형/성공/실패/소요 시간만 최소 보존.
